Guia 1

1. Componentes e Props

Um componente é uma função que retorna JSX. Assim como toda função aceita parâmetros, um componente aceita entradas — e essas entradas são as props.

O problema do componente estático

Sem props, o conteúdo do componente fica fixo. Para ter cartões diferentes seria preciso duplicar o componente inteiro — exatamente o que a programação tenta evitar.

function Card() {
  return (
    <div>
      <h1>Estudar JavaScript</h1>
      <p>Ler 10 páginas</p>
    </div>
  )
}

Props: o parâmetro do componente

O componente recebe um objeto props com todos os atributos passados na tag. Cada atributo escrito na tag vira uma chave do objeto.

function Card(props) {
  return (
    <div>
      <h1>{props.titulo}</h1>
      <p>{props.paragrafo}</p>
    </div>
  )
}

// quem usa:
<Card titulo="Estudar JavaScript" paragrafo="Ler 10 páginas" />

Desestruturando as props

Em vez de repetir props.titulo, é possível abrir o objeto direto nos parâmetros:

function Card({ titulo, paragrafo }) {
  return (
    <div>
      <h1>{titulo}</h1>
      <p>{paragrafo}</p>
    </div>
  )
}

Regra de ouro: props são somente leitura. O componente usa, mas nunca altera — quem manda no valor é quem passou a prop. Escrever titulo = "Outro" dentro do componente não atualiza a tela e quebra a previsibilidade.

RESUMO

Componente = função que retorna JSX. Props = parâmetros dessa função, um objeto acessado com props.chave ou por desestruturação. São somente leitura e tornam o componente reutilizável com dados diferentes.

2. Children

Props resolvem dados nomeados. Mas existe conteúdo sem rótulo: o que fica entre as tags de abertura e fechamento. Para isso existe a prop mais especial do React: children.

props.children

Todo componente possui, dentro de props, uma chave especial children, que guarda tudo o que foi escrito entre a tag de abertura e a de fechamento. O componente decide onde encaixar esse conteúdo.

function Caixa(props) {
  return (
    <div className="caixa">
      <h3>Aviso</h3>
      {props.children}
    </div>
  )
}

<Caixa>
  <p>Sua senha expira em 7 dias.</p>
</Caixa>

Props + children juntos, e composição

Props para dados nomeados (título, cor), children para o conteúdo aberto. É assim que se monta um app em blocos — um componente contendo outros componentes.

SituaçãoTécnicaPor quê
Dado nomeado e único (título, preço)PropsO componente sabe exatamente o que é cada valor
Conteúdo aberto, definido por quem usaChildrenNão existe limite para o que pode entrar
Incluir outros componentes dentroChildrenÉ a base da composição de interfaces
RESUMO

props.children guarda o conteúdo escrito entre as tags do componente. Não é um recurso separado — é apenas mais uma prop, preenchida automaticamente pelo React.

3. CSS Modularizado

CSS global (index.css) vale para o projeto inteiro — duas classes com o mesmo nome brigam entre si. O CSS Module dá a cada componente um estilo com escopo próprio.

Nome.module.css

/* Card.module.css */
.card {
  border: 1px solid #ddd;
  border-radius: 8px;
}

import styles from "./Card.module.css";

function Card({ titulo, children }) {
  return (
    <div className={styles.card}>
      <h1>{titulo}</h1>
      {children}
    </div>
  )
}

No build, o Vite embaralha os nomes das classes com um sufixo único por arquivo (ex: Card_titulo_1a2b3c) — por isso dois componentes podem repetir .titulo sem conflito.

CSS Global (index.css)CSS Module (Nome.module.css)
Vale para a página inteiraVale só para quem importou
Nomes de classe podem colidirNomes são embaralhados no build
Ideal para reset, fontes, variáveisIdeal para o estilo de cada componente

Armadilha clássica: escrever class="card" no JSX. O React aceita, mas o navegador não aplica o estilo — use sempre className.

RESUMO

CSS Module dá escopo local ao estilo: importe com import styles from ... e use className={'{styles.classe}'}. O global fica reservado ao que é do site inteiro.

4. Estado e Ciclo de Vida

Uma variável comum não atualiza a tela quando muda — o React simplesmente não a observa. Para a interface reagir, é preciso de estado.

function Contador() {
  let contador = 0;
  function incrementar() { contador++; }  // muda a variável...
  return (
    <div>
      <h1>Contador: {contador}</h1>   {/* ...mas a tela não sabe */}
      <button onClick={incrementar}>+1</button>
    </div>
  )
}

O clique altera a variável na memória, mas ninguém avisou o React. Para a tela mudar, a função do componente precisa rodar de novo, e isso só acontece quando o React decide que algo relevante mudou.

O que o React faz quando o estado muda

  1. Roda a função do componente de novo (re-renderiza);
  2. Compara o novo resultado com o Virtual DOM;
  3. Aplica no DOM real apenas a diferença mínima.

As três fases do ciclo de vida

FaseQuando aconteceO que o React faz
MontagemComponente aparece na tela pela 1ª vezRoda a função, cria estados iniciais, insere o JSX no DOM
AtualizaçãoUm estado muda ou novas props chegamRoda a função de novo, compara e atualiza só o necessário
DesmontagemComponente sai da telaRemove o JSX do DOM e esquece os estados
RESUMO

Variável comum "reseta" a cada renderização, porque vive dentro da função. O estado é guardado pelo React fora da função e sobrevive entre renderizações — é a memória observada do componente.

5. Estado com useState

useState é o hook que conecta o componente ao funcionamento interno do React, criando um dado observado.

import { useState } from "react";

function Contador() {
  const [contador, setContador] = useState(0);
  //     ^valor atual  ^função de atualizar   ^valor inicial

  function incrementar() {
    setContador(contador + 1)
  }

  return (
    <div>
      <h1>Contador: {contador}</h1>
      <button onClick={incrementar}>+1</button>
    </div>
  )
}

useState(0) devolve um array de duas posições, e a desestruturação de vetor "abre" esse array:

PosiçãoNome usualFunção
0contadorLer / exibir o valor atual
1setContadorAtualizar o valor e disparar a re-renderização

Regras dos hooks: só dentro de componentes; sempre no topo da função (nunca em if, for ou dentro de return); sempre na mesma ordem em toda renderização.

Evite setContador(contador++) — o ++ devolve o valor antigo. Calcule sempre fora: setContador(contador + 1).

RESUMO

useState(inicial) devolve [valor, setValor]. A função set atualiza o estado e avisa o React, que re-renderiza o componente.

6. Funções: tipos, parâmetros e retorno

Todo componente React é uma função que recebe props e retorna JSX — dominar as formas de escrever função é pré-requisito direto.

// 1) Declaração — pode ser chamada antes de aparecer no arquivo
function dobrar(n) { return n * 2; }

// 2) Expressão — a função vira um valor guardado numa variável
const triplicar = function (n) { return n * 3; };

// 3) Arrow function — padrão em código moderno e no React
const quadruplicar = (n) => { return n * 4; };

// retorno implícito: sem chaves, a expressão JÁ é o retorno
const somarCurta = (a, b) => a + b;

// 4) Função assíncrona
async function buscarUsuario() {
  const resposta = await fetch("https://api.exemplo.com/usuario");
  return await resposta.json();
}
TipoSintaxeObservação
Declaraçãofunction nome(){}Aceita hoisting
Expressãoconst n = function(){}Só existe após a atribuição
Arrowconst n = () => {}Mais curta; padrão em eventos JSX

Arrow function com chaves não retorna nada automaticamente: (a,b) => { a + b } devolve undefined. Retorno implícito só vale sem chaves.

RESUMO

Quatro tipos de função: declaração, expressão, arrow (com retorno implícito sem chaves) e async (com await, sempre devolvendo uma Promise).

7. Callback

Função é um valor: pode ser guardada, passada como argumento e executada por outra função. Uma função entregue a outra para ser chamada depois é um callback.

function avisar() { console.log("Nova mensagem!"); }

avisar;   // apenas a referência, nada acontece
avisar(); // executa AGORA

function processarPedido(cliente, acao) {
  console.log(`Processando pedido de ${cliente}...`);
  acao(); // chamando de volta
}
processarPedido("Ana", () => console.log("Enviando e-mail"));

Callback nos eventos do React

EscritaO que acontece
onClick={'{avisar}'}Executa quando o usuário clicar — correto
onClick={'{() => avisar("oi")}'}Executa no clique, com argumento — correto
onClick={'{avisar()}'}Executa imediatamente ao renderizar — erro clássico
RESUMO

Com parênteses você executa na hora (avisar()); sem parênteses você entrega a referência (avisar). Argumentos exigem uma arrow function envolvendo a chamada.

8. Métodos de iteração de vetor

forEach, map, filter e reduce recebem um callback executado item a item — quem controla o percurso é o método; você entrega apenas o comportamento.

const produtos = [
  { nome: "Teclado", preco: 150 },
  { nome: "Mouse", preco: 80 },
  { nome: "Monitor", preco: 900 }
];

// map: transforma cada item, devolve vetor do MESMO tamanho
const etiquetas = produtos.map(p => `${p.nome} - R$ ${p.preco}`);

// filter: seleciona itens, devolve vetor igual ou MENOR
const caros = produtos.filter(p => p.preco > 100);

// reduce: acumula tudo em um único valor
const total = produtos.reduce((acc, item) => acc + item.preco, 0);
MétodoCallback devolveRetorno do métodoNo lugar de qual for?
forEachNada (só efeito)undefinedLoop simples, sem contador
mapItem transformadoNovo vetor (mesmo tamanho)for + vetor auxiliar + push
filtertrue / falseNovo vetor (igual ou menor)for + if + push
reduceO acumulado até aliUm único valorfor + variável acumuladora

No React: listas com map + key

<ul>
  {produtos.map((produto) => (
    <li key={produto.nome}>
      {produto.nome} - R$ {produto.preco}
    </li>
  ))}
</ul>

É porque o map devolve um vetor que ele entra direto no JSX — com forEach não funcionaria, pois devolve undefined. A prop key deve ser um valor único e estável (id, nome), nunca o índice.

RESUMO

map, filter e reduce nunca alteram o vetor original — produzem um resultado novo. Só o map alimenta listas no JSX, sempre acompanhado de key.

9. Desestruturação: objetos e vetores

Desestruturar é "abrir" um objeto ou vetor e extrair valores direto para variáveis, em uma linha só. Aparece no useState e na leitura de props.

// OBJETO — extração pelo NOME da propriedade
const aluno = { nome: "Ana", curso: "2ADS" };
const { nome, curso } = aluno;

// renomear e valor padrão
const { titulo: nomeProduto, desconto = 0 } = produto;

// VETOR — extração pela POSIÇÃO
const notas = [9.5, 7.0, 8.5];
const [primeira, segunda] = notas;
const [ , , terceira ] = notas; // pulando posições
CritérioObjeto { }Vetor [ ]
Extração porNome da propriedadePosição (índice)
Ordem importa?NãoSim
Exemplo no ReactProps: {'{ nome, preco }'}useState: [valor, setValor]
RESUMO

Chaves abrem objeto (por nome); colchetes abrem vetor (por posição). No React, props são objetos e o retorno do useState é vetor.

10. Operador ternário

Forma compacta de decidir entre dois valores: condição ? seTrue : seFalse. É a ferramenta padrão de renderização condicional no React.

const categoria = idade >= 18 ? "adulto" : "menor";

// dentro do JSX:
{logado ? (
  <p>Bem-vindo de volta!</p>
) : (
  <p>Faça o login para continuar</p>
)}
<button>{logado ? "Sair" : "Entrar"}</button>
Critérioif / elseTernário
O que éInstrução (executa blocos)Expressão (devolve um valor)
Funciona dentro do JSX?NãoSim — entre chaves { }

Ternários podem se encadear (nota >= 9 ? "A" : nota >= 7 ? "B" : "C"), mas acima de três caminhos considere voltar ao if/else para manter a leitura.

RESUMO

O ternário devolve um valor, por isso funciona dentro das chaves do JSX para trocar textos, atributos ou componentes conforme o estado.

11. Operadores lógicos && e ||

Em JavaScript, && e || devolvem um dos operandos (não apenas um booleano) e param assim que a resposta já está garantida — o curto-circuito.

ValorClassificação
false, 0, "", null, undefined, NaNfalsy
Qualquer outro (inclusive "0", [] e {'{}'})truthy
// || devolve o primeiro TRUTHY
const exibicao = nome || "Visitante";

// && devolve o primeiro FALSY (ou o último)
const mensagem = logado && "Bem-vindo!";

// No JSX:
{erros.length > 0 && <p>Corrija os campos</p>}
<h1>Olá, {nome || "visitante"}!</h1>

O || trata 0 como falsy: se curtidas valer 0, {'{curtidas || "-"}'} mostraria "-" indevidamente. Para números onde zero é válido, teste explicitamente.

RESUMO

|| = primeiro truthy (valor padrão). && = primeiro falsy, ou o último (renderização condicional no JSX).

12. Promises e fetch

Uma Promise representa um valor que ainda vai chegar. O fetch faz pedidos HTTP e devolve uma Promise.

EstadoSignificado
pendingEm andamento, sem resultado ainda
fulfilledConcluída com sucesso
rejectedFalhou (tem um erro)
// .then / .catch
fetch("https://api.exemplo.com/usuarios")
  .then((resposta) => resposta.json())
  .then((dados) => console.log(dados))
  .catch((erro) => console.log("Falhou:", erro));

// async/await + try/catch
async function carregarUsuarios() {
  try {
    const resposta = await fetch("https://api.exemplo.com/usuarios");
    if (!resposta.ok) throw new Error(`Erro ${'${resposta.status}'}`);
    const dados = await resposta.json();
  } catch (erro) {
    console.log("Falhou:", erro.message);
  }
}

Esquecer o await antes de resposta.json() deixa uma Promise pendente na mão, não os dados já convertidos.

RESUMO

fetch dispara o pedido e devolve uma Promise. No React, espelhe os estados da Promise em estados do componente: carregando, erro e dados.

13. Eventos no React: campos de entrada

O valor digitado não mora no HTML — mora no estado. O campo de entrada é só a ponte entre o teclado e esse estado.

function Saudacao() {
  const [nome, setNome] = useState("");
  return (
    <div>
      <input
        value={nome}
        onChange={(e) => setNome(e.target.value)}
      />
      <h1>Olá, {nome || "visitante"}!</h1>
    </div>
  )
}

O acordo de um campo controlado tem três cláusulas: o estado guarda o texto (value={'{nome}'}); a cada tecla, onChange atualiza o estado; a re-renderização devolve o texto novo ao campo.

PropriedadeO que é
eO objeto do evento, entregue pelo React
e.targetO elemento do DOM que disparou o evento
e.target.valueO valor atual do campo

Controlado × não controlado: sem value + estado, o input guarda o texto sozinho e o React fica fora do jogo.

RESUMO

Padrão controlado: o estado guarda o texto, onChange captura cada tecla via e.target.value, e value devolve o texto ao campo.

14. Enviando dados: fetch com POST

Para um dado digitado sobreviver ao fechar a aba, ele precisa cruzar a rede até um servidor.

VerboObjetivoOnde os dados viajam
GETPedir dadosNa URL
POSTEnviar dadosNo corpo da requisição
const resposta = await fetch("https://api.minhaloja.com/usuarios", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ nome: nome })
});

if (!resposta.ok) { setMensagem("Erro " + resposta.status); return; }
const dados = await resposta.json();
setMensagem(dados.mensagem);

Por que JSON.stringify()? O corpo de uma requisição HTTP é sempre texto — um objeto JS não atravessa a rede sozinho. A etiqueta Content-Type: application/json precisa acompanhar.

Por que não <form>? Um formulário recarrega a página ao ser enviado. Um botão comum disparando por onClick mantém quem manda na página como o React.

RESUMO

Ciclo completo: estado → texto JSON (JSON.stringify) → rede → servidor → resposta → resposta.json() → estado.
